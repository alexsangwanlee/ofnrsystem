# 견적서

## 먼저 읽을 것

- 회사 지식: 이 스킬 폴더 기준 `../../knowledge/company.md`
- 결과물 공통 규칙: 이 스킬 폴더 기준 `../../knowledge/output-rules.md`

## 결과물

- `01_PLAN/{작업번호}_QUOTE_v{NN}.xlsx`
- 가능하면 같은 이름의 PDF도 만든다(Excel로 내보내기).

## 순서

1. `get_project`, `get_mail_thread`, `01_PLAN`의 BRIEF와 이전 견적서를 읽는다.
2. 작업 프롬프트에 회사 양식 경로가 있으면 그 파일을 복사해 새 버전 파일을 만들고 값만 채운다. 서식, 수식, 로고는 건드리지 않는다.
3. 양식이 없으면 아래 기본 구성으로 만든다.
4. 단가와 수량은 대표의 지시, 이전 견적서, 학습된 규칙에서만 가져온다. 없으면 빈 칸으로 두고 노란 배경과 `확인 필요` 메모를 단다.
5. 합계는 수식으로 계산한다(값을 손으로 적지 않는다).
6. 저장 후 파일을 다시 열어 수식 오류(#REF!, #VALUE!)가 없는지 확인한다.

## 기본 구성 (회사 양식이 없을 때)

- 머리: `견 적 서`, 견적일, 유효기간(`확인 필요`), 공급받는자(거래처), 공급자(회사 지식의 상호, 사업자번호, 대표자, 주소, 연락처), 프로젝트명.
- 항목 표: 구분, 항목, 규격, 수량, 단위, 단가, 금액(수량 x 단가), 비고.
- 구분은 홈페이지 기준 세 가지로 시작한다: 디자인비, 시공비, 운영비. 프로젝트에 필요하면 학습된 규칙에 따라 더 나눈다.
- 아래: 공급가액 합계, 부가세(공급가액의 10%), 총액.
- 글꼴: 맑은 고딕 또는 Pretendard.

## 하지 않는 것

- 단가를 지어내지 않는다.
- 할인이나 조건을 임의로 넣지 않는다.

## 처음 쓸 때 대표에게 확인할 것

아래가 학습된 규칙에 없으면, 견적서를 만든 뒤 마지막 보고에 질문으로 남긴다. 대표의 답은 스킬 학습으로 규칙이 된다.

- 항목 분류: 디자인비, 시공비, 운영비 아래 세부 항목을 어떻게 나누는가
- 일반관리비와 이윤(또는 대행수수료)을 별도 행으로 넣는가, 넣는다면 비율은
- 금액 절사 규칙 (원 단위, 천원 단위)
- 견적 유효기간
- VAT 포함 표기 방식
- 결제 조건(선금, 잔금) 표기 여부
