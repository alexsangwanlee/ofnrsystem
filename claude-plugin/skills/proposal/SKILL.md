# 제안서

## 먼저 읽을 것

- 회사 지식: 이 스킬 폴더 기준 `../../knowledge/company.md`
- 결과물 공통 규칙: 이 스킬 폴더 기준 `../../knowledge/output-rules.md`

## 결과물

- `01_PLAN/{작업번호}_PROP_v{NN}.pptx`
- 가능하면 같은 이름의 PDF도 만든다(export 도구의 export-to-pdf).

## 만드는 도구

- 파일은 파워포인트 MCP 도구(`mcp__powerpoint__*`)로만 만든다. 이 작업에는 Bash가 없으니 pptx 문서 스킬(pptxgenjs, python 스크립트)은 쓰지 않는다.
- 회사 마스터 양식이 있으면 presentation 도구로 양식을 열고 바로 save-as로 결과물 이름에 저장한 뒤 만든다. 양식 파일은 고치지 않는다.

## 순서

1. `get_project`, BRIEF, 견적서, `02_DESIGN`의 렌더 이미지, 받은 자료를 읽는다.
2. 슬라이드 계획을 먼저 세운다(슬라이드마다 제목과 핵심 메시지 한 줄).
3. 회사 마스터 양식이 있으면 그 레이아웃으로 만든다. 없으면 기본 구성으로 만든다.
4. 3D 렌더와 그래픽 이미지가 있으면 해당 슬라이드에 넣는다. 없으면 이미지 자리를 비우고 `이미지 필요`라고 적는다.
5. 저장 후 export 도구의 export-all-slides-to-images로 슬라이드 이미지를 현재 폴더(작업 폴더)에 만들어 한글 글자 넘침, 겹침이 없는지 본다.

## 기본 구성 (회사 양식이 없을 때)

오프너 서비스의 진행 방식을 따른다.

1. 표지: 프로젝트명, 거래처, 날짜, 오프너
2. 이해: 브랜드 상황과 목표, KPI (PLAN Discover, Define)
3. 타겟과 인사이트: 누가 왜 오는가
4. 컨셉: 한 문장 컨셉과 핵심 메시지
5. 공간: 조닝, 동선, 포토존 (DESIGN). 3D 렌더 이미지
6. 콘텐츠와 체험: 체험 요소, 굿즈
7. 운영: 인력, 대기열, 일일 리포트 (SYSTEM)
8. 확산: 티저, 인플루언서, SNS 이벤트, 측정 지표 (VIRAL)
9. 일정: 준비부터 철수까지
10. 예산 요약: 견적서의 디자인비, 시공비, 운영비 합계
11. 회사 소개: 회사 지식 문서의 강점과 포트폴리오

## 원칙

- 홈페이지 원칙을 반영한다: 줄 설 이유를 먼저 설계한다, 찍고 싶은 공간이 팔린다, 한 팀이 끝까지 맡는다.
- 숫자(예상 방문객, 도달)는 근거가 없으면 쓰지 않는다.
