# 요구사항 정리 (BRIEF)

## 먼저 읽을 것

- 회사 지식: 이 스킬 폴더 기준 `../../knowledge/company.md`
- 결과물 공통 규칙: 이 스킬 폴더 기준 `../../knowledge/output-rules.md`

## 결과물

- `01_PLAN/{작업번호}_BRIEF_v{NN}.md` 한 개.

## 구성

오프너 PLAN 단계의 Discover와 Define 기준으로 정리한다.

1. 개요: 브랜드, 프로젝트 종류, 기간, 장소, 면적, 예산, 마감 (모르면 `확인 필요`)
2. 목적과 KPI: 방문자 수, 체험 전환, 콘텐츠 확산 중 무엇이 목적인지. 메일에 없으면 질문으로 남긴다.
3. 타겟: 메일과 자료에서 확인되는 타겟. 추측은 `가설`로 표시한다.
4. 경쟁과 맥락: 같은 기간, 같은 지역 팝업이나 행사 언급이 있으면 정리한다.
5. 공간과 동선 조건: 장소 제약, 설치/철수 시간, 층고, 전기 등 확인된 것.
6. 범위: PLAN, DESIGN, SYSTEM, VIRAL 중 요청받은 범위.
7. 거래처에 물어볼 질문: 견적과 제안에 꼭 필요한데 빠진 정보. 우선순위 순.
8. 일정 메모: 회사 기준 준비 기간(최소 4-6주)과 비교해 촉박한지.
